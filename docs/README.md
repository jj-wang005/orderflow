## 处理流程

1. 配置客户字段映射和匹配规则，保存配置版本。
2. 上传 Excel，或将 PDF、图片、文本解析为待确认草稿。
3. 校验客户字段、标准化数据，按客户规则寻找合格历史订单。
4. 复用明确的产品与有效参考单价，按本次采购数量计算金额；不确定的采购行进入人工处理。
5. 保存任务及逐行结果，提供订单查询、编辑、状态变更、作废和导出。

请求幂等控制重试，跨任务重复采购需人工核实。AI 结果先形成草稿，确认导入后才进入正式订单处理。

## 模块职责

| 目录或文件 | 职责 |
| --- | --- |
| `app/api/` | HTTP 接口、请求校验与错误响应 |
| `app/services/` | 解析、匹配、建单、人工处理、订单导出及助手 |
| `app/models/`、`app/repositories/` | 数据模型与数据库查询 |
| `app/schemas/` | 输入输出结构及字段约束 |
| `app/core/` | 配置、数据库连接与环境限制 |
| `app/knowledge/` | C豆的系统说明与业务知识 |
| `frontend/src/` | 页面、组件、接口封装和操作缓存 |
| `alembic/versions/` | 数据库增量迁移 |
| `tests/` | 后端测试、事务回滚与临时 schema 防护 |
| `scripts/environment_admin.py` | 环境初始化、备份、重置与恢复 |

## 实现边界

项目用于受控本地演示，尚无登录鉴权，未接入真实 OMS/ERP。样例产品和历史价格为模拟数据。C豆不直接读取或操作业务订单；外部模型调用需要配置和用户授权。演示、测试、历史环境具有不同写入限制。

内部缓存键、维护锁和运行账户保留兼容命名，不代表界面品牌；避免更名导致现有草稿、请求标识或数据库权限失效。

上传版不包含原开发过程报告、数据库快照、聊天记录和旧截图；维护脚本执行时可以在本地生成报告。测试结果需在对应环境实际运行，不能以源码存在代替运行验证。
